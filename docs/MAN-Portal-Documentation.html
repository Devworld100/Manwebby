1 System Overview

The MAN Commercial Protection Beneficiary Account Management & Portal is a single-page, role-based web application embedded in login.html. It provides two distinct authenticated views:

Area Role Access Type Purpose
User Dashboard user Read-Only (Protected) View vault deposit details, demurrage accrual, Certificate of Deposit, and submit 2-Day Collection Notice
Admin Portal admin Full CRUD (Restricted) Manage all user profiles, dynamic name reassignment, certificate preview, statistics, and search/filter tools
Important: All data is persisted in the browser's localStorage (profiles) and sessionStorage (active session). There is no backend server — this is a fully client-side demonstration system.

3.3 Authentication Flow

1. User enters credentials → submits form
2. portal.js calls PortalData.authenticate(identifier, password)
3. Data layer checks Admin credentials first (hardcoded), then searches user profiles
4a. ✓ Success (Admin) → Session stored → Admin Portal rendered
4b. ✓ Success (User) → Session stored → User Dashboard rendered
4c. ✗ Failure → Error alert shown + toast notification
5. syncPortalNavState() updates topbar/nav link to reflect logged-in state

3.4 Authentication Rules

RuleDetail
Admin detection Username/email matches admin@mancommercial.co.uk or literal admin, AND password is AdminPass2024!
User detection Username OR email matches a profile record, AND password matches the stored value
Suspended/Inactive If a matched profile has status Suspended or Inactive, login is rejected with a deactivation message
Case handling Identifier comparison is case-insensitive (lowercased before matching)
Session persistence Stored in sessionStorage — survives page reloads but clears when the tab is closed

8 Navigation Session Sync

portal-nav.js provides the syncPortalNavState() function, which runs on page load (DOMContentLoaded) and is called explicitly by portal.js on login/logout events.

8.1 Nav State by Auth Status

ComponentLogged OutLogged In (User)Logged In (Admin)
Nav Link Login 👤 {Name} ACTIVE (gold) 🛡️ Admin Console (gold)
Topbar Button 🔒 LOGIN (outline) ✅ {NAME} (gold bg) + red ⏻ logout 🛡️ ADMIN CONSOLE (gold bg) + red ⏻ logout
The nav sync works globally across all pages — not just login.html. If a user is logged in and navigates to services.html, the topbar will still display their authenticated state with a quick-logout power button.

8.2 Detail Link Routing

portal-nav.js also rewrites internal anchor links (e.g. services.html#event) to route to the shared detail page (details.html?page=event-security). This is handled by the connectDetailLinks() function and the detailLinks lookup table.

10 Security Notes & Production Recommendations

Online Deployment Ready: The portal now includes a dedicated server-side SQLite Database (db.js with WAL mode) and REST API endpoints (/api/auth/login, /api/profiles, /api/collection-notice). All testing fields and 1-click demo buttons have been removed from the client interface for live deployment.
ConcernCurrent StateProduction Recommendation
Password Storage Plaintext in localStorage Server-side bcrypt/argon2 hashing with salting
Authentication Client-side JS comparison Server-side JWT/session token authentication with refresh tokens
Data Persistence Browser localStorage PostgreSQL/MongoDB with encryption-at-rest and regular backups
Session Management sessionStorage (no expiry) HTTP-only secure cookies with expiry, CSRF protection
Input Sanitisation Basic escapeHtml() on display Full XSS prevention + server-side validation and parameterised queries
Transport Security Not enforced Mandatory HTTPS (TLS/SSL) with HSTS headers
RBAC Two roles (admin/user) hardcoded Configurable role-based permissions with policy engine
Audit Logging Appended to context_details Dedicated audit trail table with immutable, timestamped records
